ASTRA STORE — CHECKOUT COM MYSQL (SEM PROCESSADOR DE PAGAMENTO)
==============================================================

ESTA VERSAO NAO USA MERCADO PAGO NEM OUTRO PROCESSADOR. Ela registra o pedido
no MySQL e mostra uma confirmacao de pedido recebido. Ela NAO cobra nem valida
cartoes.

IMPORTANTE SOBRE CARTOES
-----------------------
Por seguranca, a loja nao pede nem armazena numero completo do cartao, validade
ou CVV/CVC. O banco guarda somente nome do titular, tipo (credito/debito),
bandeira, quatro ultimos digitos e parcelas. Sem um adquirente/processador nao
ha como validar o cartao ou confirmar uma cobranca. O pedido fica com pagamento
nao processado; nao altere esse status para pago apenas porque o cliente clicou
em Finalizar pedido.

1. CRIAR O BANCO NO MYSQL WORKBENCH
----------------------------------
Para uma instalacao nova:
1. Abra o MySQL Workbench e conecte ao seu servidor MySQL.
2. Abra database/schema.sql dentro desta pasta.
3. Execute o arquivo inteiro (icone do raio).
4. O banco astra_store e as tabelas customers, orders, order_items e payments
   serao criados.

Se voce ja tinha instalado uma versao antiga deste projeto, NAO execute o
schema.sql por cima esperando que ele altere tabelas existentes. Use as
migracoes conforme a versao do banco:
- 001-remove-pix-column.sql: somente se a coluna Pix antiga ainda existir.
- 002-manual-checkout-address.sql: somente se os campos CPF/endereco ainda nao
  tiverem sido adicionados.
- 003-cardholder-name.sql: uma vez para adicionar o nome do titular do cartao.

2. CONFIGURAR A CONEXAO COM O MYSQL
-----------------------------------
1. Instale Node.js 18 ou superior.
2. Copie .env.example e renomeie a copia para .env (o iniciar-loja.bat faz isso).
3. Abra .env e preencha DB_HOST, DB_PORT, DB_NAME, DB_USER e DB_PASSWORD com os
   dados da sua instalacao MySQL. Normalmente DB_HOST=127.0.0.1, DB_PORT=3306 e
   DB_NAME=astra_store; usuario e senha dependem da sua instalacao.
4. Salve o arquivo .env. NUNCA coloque a senha no script.js ou index.html.

3. COMO INICIAR (CORRIGE O ERRO HTTP 405)
-----------------------------------------
No Windows, de dois cliques em iniciar-loja.bat. O arquivo instala dependencias
quando necessario, verifica a sintaxe e inicia o servidor Node.js.

Depois abra exatamente:
http://localhost:3000

NAO abra index.html diretamente e NAO use a extensao Live Server do VS Code.
Live Server e hospedagem estatica nao executam as rotas POST da API, causando
o erro HTTP 405 que aparece no checkout. O site e a API precisam ser servidos
pelo mesmo servidor Node.js deste projeto.

Tambem e possivel iniciar manualmente no terminal, dentro desta pasta:
  npm install
  npm run check
  npm run dev

Mantenha o terminal aberto enquanto a loja estiver em uso. Para parar, use
Ctrl+C. Se mudar o .env, reinicie o servidor.

4. COMO O CHECKOUT FUNCIONA
---------------------------
1. O cliente adiciona produtos a sacola.
2. Preenche nome, e-mail, telefone opcional, CPF e endereco de entrega.
3. Ao clicar em Continuar para dados do cartao, POST /api/checkout/start valida
   os dados e grava comprador, endereco, itens e pedido no MySQL.
4. O checkout avanca para a segunda etapa, onde o cliente informa nome impresso
   no cartao, modalidade, bandeira, quatro ultimos digitos e parcelas.
5. Ao clicar em Finalizar pedido, POST /api/checkout/complete associa esses
   metadados ao pedido no MySQL e atualiza o status para recebido.
6. A tela informa que o pedido foi registrado com sucesso e esclarece que
   nenhuma cobranca foi realizada.

5. DIAGNOSTICO
--------------
- Abra http://localhost:3000/api/health para verificar se o servidor alcança
  o MySQL. O resultado precisa mostrar ok=true e database=connected.
- Se aparecer database=disconnected, verifique as credenciais do .env e se o
  MySQL esta ligado; confirme tambem que database/schema.sql foi executado.
- Se aparecer erro 405, provavelmente a loja foi aberta pelo Live Server ou
  por hospedagem estatica. Feche essa aba e use http://localhost:3000.
- Se aparecer erro 503 ao gravar, a API esta ativa, mas o banco nao conectou.

6. ROTAS
--------
GET  /api/health
POST /api/checkout/start
POST /api/checkout/complete

7. DADOS ARMAZENADOS
--------------------
customers: nome, e-mail, CPF, telefone;
orders: valores, status, metodo e endereco de entrega completo;
order_items: produto, tamanho, quantidade e preco;
payments: nome do titular, tipo, bandeira, quatro ultimos digitos, parcelas,
valor e status.

Nao sao armazenados numero completo, validade ou CVV/CVC do cartao.

8. ANTES DE PUBLICAR
--------------------
- Esta versao e um registro de pedidos, nao um sistema de cobranca.
- Proteja o servidor, o arquivo .env e o acesso ao MySQL.
- Configure HTTPS e controle de acesso administrativo.
- Atualize os precos e o estoque em catalog.json.
- Crie aviso de privacidade para o tratamento de nome, CPF, contato e endereco.
- Para receber pagamentos reais, sera necessario contratar um adquirente ou
  processador e integrar seus campos/tokenizacao seguros.
